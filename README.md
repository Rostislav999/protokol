# ОЗтаУСЯ

## Установщик Windows с отдельным окном

Автономная версия включает Python, Tesseract, модели `ukr`, `rus`, `eng` и
движок интерфейса. Предварительная установка этих компонентов и браузер для
работы не нужны. Установка и обычная работа не требуют интернета. Поддерживаются
Windows 10 (1809 и новее) и Windows 11, 64-разрядные.

Установщик собирается в [Actions → Windows installer](https://github.com/Rostislav999/protokol/actions/workflows/windows-installer.yml).
Откройте **успешно завершённую** сборку, скачайте **Artifacts → Protokol-Windows-Installer**,
распакуйте архив и запустите `Protokol-Setup-1.6.2-win64.exe`. Исходный ZIP по
ссылке ниже — другой вариант запуска, он по-прежнему требует Python и Tesseract.
Артефакты сборок хранятся 30 дней; при необходимости запустите **Run workflow**.

Программа устанавливается для текущего пользователя, создаёт ярлык в меню
«Пуск» и по выбору на рабочем столе. Открывается собственное окно «ОЗтаУСЯ»,
без вкладки браузера и консоли. Для сохранения Word, ZIP и Excel используется
обычное окно выбора файла. Обработка документов выполняется на компьютере;
встроенное окно разрешает сетевые запросы только к собственному локальному серверу.

Справочники, шаблоны и нумерация хранятся в `%LOCALAPPDATA%\Protokol\data`,
как в прежнем Windows-запуске. Обновление и удаление программы эту папку не
удаляют. Название ярлыка, окна и установщика — «ОЗтаУСЯ»; значок подготовлен
по присланной эмблеме. При обновлении прежние ярлыки «Протокол» заменяются
новыми. Журнал запуска — `%LOCALAPPDATA%\Protokol\logs\desktop.log`.
Для прямой печати заданий через Microsoft Word по-прежнему нужен установленный
Word; создание Word- и Excel-файлов его не требует.

Инструкции самостоятельной сборки и состав установщика:
[packaging/README.md](packaging/README.md).

## Запуск из исходного ZIP

[Скачать программу ZIP](https://github.com/Rostislav999/protokol/archive/refs/heads/main.zip)

Скачайте и распакуйте архив целиком. **На Windows запустите двойным щелчком `START_WINDOWS.bat` в корне распакованной папки.** Он подготовит зависимости и откроет программу в браузере. Для запуска нужны Python 3.12 (рекомендуется) или 3.13 и Tesseract OCR 5; если их нет, окно запуска сообщит, что установить.

Локальная программа для подготовки Word-протоколов, заданий на исследования и Excel-таблицы по акту отбора образцов. Загружаете акт, проверяете позиции и шаблоны, скачиваете Word-файлы. Excel можно подготовить прямо из формы акта либо заполнить прежнюю таблицу из DOCX, PDF или ZIP с протоколами.

В библиотеку протоколов включены 22 предоставленных образца: мясные и рыбные консервы, готовые блюда, каши, паштеты, джемы, сахар, соль и сухарики. Библиотеку можно дополнять через интерфейс без изменения программы. Отдельно добавлены 60 шаблонов заданий для трёх отделений.

## Пакеты документов

Раздел **Пакети документів** хранит отдельные дела: черновики акта, заданий,
Excel и супроводительных, исходные файлы и созданные документы. Создайте первый
пакет из текущей работы либо начните пустой. Для следующего дела создавайте новый
пустой пакет. Кнопка **Продовжити роботу** открывает все редакторы пакета;
после перезапуска последний рабочий пакет восстанавливается автоматически.
Подтверждения проверки нужно поставить заново. **Поза пакетом** возвращает
прежние общие черновики, которые хранятся отдельно.

Оригиналы сохраняются локально перед фоновым чтением. При повторном открытии
доступна ссылка на исходный акт и выбранная книга Excel. Для черновиков старых
версий исходные файлы, которые раньше не сохранялись, нужно выбрать один раз.
В карточке пакета можно добавить дополнительные документы, скачать отдельный
файл или весь комплект ZIP. ZIP содержит источники, созданные документы,
черновые данные и текстовый отчёт проверки. Предыдущие сформированные файлы
сохраняются отдельно. Архивирование дела сохраняет его содержимое; для
продолжения работы верните дело из архива.

**Перевірити комплект** сверяет номера и даты протоколов, фирмы, приложения,
число страниц доступных PDF и данные Excel. Изменённые после формирования
черновики помечают соответствующие выходные файлы как требующие обновления.
Пакет можно отметить проверенным после устранения ошибок и создания актуальных
файлов во всех заполненных разделах. Результаты испытаний и правильность
содержания документов проверяет ответственный сотрудник.

В редакторе супроводительных кнопка **Історія** показывает версии выбранного
письма и сравнение с текущим текстом. Автосохранение записывает историю;
важный вариант можно назвать и сохранить отдельно. Хранятся последние 100
версий письма, включая до 30 именованных контрольных версий, защищённых от
вытеснения обычными автосохранениями. Восстановление заменяет текст одного
письма, очищает его исходящий номер, дату и подтверждение проверки. Выданные
документы в журнале сохраняются.

В выборе шаблонов звёздочка добавляет шаблон в **Обрані**. Фильтр **Нещодавні**
показывает последние использованные шаблоны. Полная библиотека остаётся доступна.
Фоновое чтение показывает файл и страницу; **Скасувати обробку** останавливает
OCR и не применяет частичный результат. Приватный процесс Word завершает
текущий документ и закрывается; другие окна Office продолжают работать.

**Допомога** внизу меню сохраняет технический отчёт: версии компонентов,
технические события и описание проблемы. Тексты документов, файлы и справочники
в него не включаются; программа отчёт никуда не отправляет. В этом же окне
перечислены клавиши: **Ctrl+S** — сохранить, **Ctrl+Enter** — основное действие,
**Alt+1…7** — разделы, **/** — поиск, **F1** — помощь.

Пакеты, оригиналы, история и избранные шаблоны включаются в резервную копию.
При открытии одного пакета в нескольких окнах сохраняется проверка конфликтов
черновиков: изменения одного окна не перезаписывают чужую версию незаметно.

## Настройка интерфейса

Кнопка **Вигляд** вверху окна открывает настройки: светлая, тёмная или системная
тема, три размера текста, просторное или компактное расположение полей и четыре
цвета акцента. Можно выбрать начальный режим редактора супроводительных:
**Текст**, **Сторінка**, **Поруч** или автоматический по ширине окна. В узком окне
режим «Поруч» открывает текст; страницу можно включить отдельной кнопкой.

Изменения видны сразу. **Зберегти** запоминает их, **Скасувати** возвращает
предыдущий вид. **Стандартний вигляд** показывает исходные настройки, которые
также можно сохранить или отменить. Быстро увеличить текст можно селектором
**Aa** рядом с кнопкой «Вигляд».

Настройки хранятся в `appearance.json` в папке данных текущего пользователя
Windows и включаются в резервную копию. После обновления прежний размер текста
сохраняется. Оформление DOCX и PDF, поля страницы, колонтитулы и цвет штампа
не зависят от темы и размера текста в программе.

## Сохранение работы и резервные копии

Поля акта, задания и строки Excel автоматически сохраняются в локальные
черновики после редактирования. Кнопка **Зберегти чернетку** сохраняет изменения
сразу. При следующем запуске нажмите **Відновити** возле нужного раздела.
Подтверждения проверки не восстанавливаются: перед новым экспортом проверьте
данные ещё раз. При закрытии отдельного окна программа дожидается сохранения
последних правок; при ошибке позволяет остаться в программе.

Черновики сохраняют распознанный текст, значения, ручные исправления и выбор
шаблонов, но не исходные PDF/фото и не открытый файл Excel. Для просмотра
оригинала его нужно выбрать заново. Excel создаётся по встроенной форме УБХП без повторного выбора книги.
Две открытые копии программы не могут незаметно перезаписать чужую черновую
версию: при конфликте предлагается выбрать сохранённые или текущие данные.

В **Резервні копії** можно скачать ZIP со справочниками, обеими библиотеками
шаблонов, базой нумерации и выданных заданий и сохранёнными черновиками. Храните
такую копию также на другом носителе. Перед первым запуском новой версии с
существующими данными, до их преобразования, создаётся автоматическая копия;
последние семь таких копий хранятся отдельно от данных и доступны для скачивания
в этом же окне. OCR-модели и временные файлы в копию не включаются.

Для восстановления выберите ZIP и подтвердите замену. Нумерация и остальные
данные возвращаются к состоянию копии. Перед заменой программа сохраняет
текущие данные отдельно. Неполные, повреждённые и неподдерживаемые архивы
отклоняются до замены; при ошибке применения возвращается прежний каталог.

## Проверка и источники значений

Кнопка **Перевірити перед експортом** собирает ошибки и предупреждения из
заполненных разделов. Возле каждой проблемы есть переход к соответствующему
полю. Такая же проверка открывается перед созданием протоколов, заданий и Excel.
Ошибки обязательных полей, неверные даты, повторяющиеся номера и отсутствующие
шаблоны нужно исправить. Предупреждения позволяют продолжить после проверки.

Рядом с полями указано происхождение значения: акт или протокол, справочник,
шаблон, расчёт/наследование либо ручное редактирование. При восстановлении
черновика эти отметки сохраняются. Они описывают источник, а не гарантируют
точность распознавания; результаты испытаний требуют отдельной проверки.

## Что меняется в протоколе

Программа заполняет вступительные сведения до фразы:

> Вищезазначена інформація надана замовником.

После этой фразы заполняются уже существующие строки **Акт відбору зразків**, **Номер пломби** и **Вага зразка**. Номер и название также обновляются в строке образца внутри таблицы; её разделитель, шрифт и оформление сохраняются. В строке **Мета випробувань зразка** заменяется название только до слов «на відповідність». В **Висновку** заменяются номер после «Представлений зразок» и размер партии после «відібраний від партії». Оставшийся текст заключения и сведения о результатах сохраняются из образца. Новые строки в документ не добавляются. Номер протокола обновляется во всех колонтитулах.

**Чёрный текст** — значения, подставленные программой. **Красный текст** — информация, оставшаяся из шаблона, включая результаты испытаний, утверждения о соответствии, подписи и статические реквизиты. Это проект протокола: цвет помогает проверить сохранённые сведения; программа не рассчитывает и не подтверждает новые результаты испытаний.

Старые данные заказчика и образца из начала шаблона не используются как значения по умолчанию. Незаданные поля получают отметку `[НЕ ЗАПОВНЕНО]`. Номер и дату протокола задайте в первой позиции и проверьте в остальных: дата акта не считается датой протокола.

Дата протокола оформляется как **29 жовтня 2026 року**. Можно ввести `29.10.2026` или `2026-10-29`: после выхода из поля и в готовом Word-файле дата будет записана словами. Номер и дата акта читаются из его заголовка, а пломбы — из соответствующей строки или колонки, включая **Сейф-пакет №**. В протокол переносится только первый номер пломбы, цифрами и с начальными нулями: `№1 00004850; №2 00004849` → `00004850`. Общую пломбу указывайте только когда она действительно одна для всех образцов; отдельное значение позиции имеет приоритет.

Вага зразка читается из общей массы отобранного образца и числа упаковок, например **9 ж/б по 525 г (4,725 кг).** Масса одной упаковки используется для расчёта до очистки названия; в само найменування зразка она не переносится. Размер всей партии не считается весом образца. Если данных в акте нет, после выбора шаблона предлагается его вес с соответствующей подсказкой. Поле доступно для изменения; явно очищенное поле остаётся незаполненным.

## Установка и запуск

Нужны Python 3.12 или новее и Tesseract OCR 5. Node.js, Microsoft Word и платные API для работы сервера не требуются. Word или совместимый редактор понадобится для просмотра и окончательной проверки документов.

### Linux или macOS

Установите Python с модулем `venv` и Tesseract через пакетный менеджер своей системы. Например, для Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install python3-venv tesseract-ocr
```

Версия Python в системе должна быть не ниже 3.12. Для macOS с Homebrew:

```bash
brew install python@3.12 tesseract
```

В каталоге проекта выполните:

```bash
./scripts/setup.sh
./scripts/run.sh
```

Если нужный Python вызывается другим именем, используйте, например, `PROTOKOL_PYTHON=python3.12 ./scripts/setup.sh`.

Установочный скрипт создаёт `.venv`, устанавливает зависимости и устанавливает официальные модели `ukr`, `rus`, `eng` из включённой в ZIP папки `assets/tessdata` в `.local/tessdata`, без скачивания моделей. Распаковывайте архив целиком. Если комплектные модели отсутствуют или повреждены, программа попробует загрузить их с официального сервера. Модели закреплены за конкретным коммитом проекта `tesseract-ocr/tessdata_fast`; перед использованием проверяется SHA-256. Зависимости закреплены с контрольными суммами в `requirements.lock`. Повторный запуск проверяет имеющиеся модели и устанавливает закреплённые зависимости, не сбрасывая библиотеку.

Для первой установки нужен HTTPS-доступ к PyPI и `raw.githubusercontent.com`. После установки распознавание и генерация выполняются локально. Проверки TLS и контрольных сумм отключать не нужно.

После запуска откройте в браузере адрес `http://127.0.0.1:8000`. Для другого порта: `PROTOKOL_PORT=8001 ./scripts/run.sh`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

### Windows

1. Закройте предыдущее окно запуска программы, если оно открыто. Распакуйте **весь** ZIP, не запускайте файлы прямо внутри архива.
2. Установите [Python 3.12 для Windows](https://www.python.org/downloads/windows/) (или 3.13). При установке включите **Add python.exe to PATH**. Набор закреплённых зависимостей рассчитан на эти версии; Python 3.14 пока не поддерживается файлом запуска.
3. Установите Tesseract OCR 5 по [инструкции Tesseract](https://tesseract-ocr.github.io/tessdoc/Installation.html). Файл запуска ищет `tesseract.exe` в `PATH`, `C:\Program Files\Tesseract-OCR` и стандартных пользовательских каталогах.
4. Дважды щёлкните **`START_WINDOWS.bat`**, лежащий рядом с `README.md` и папкой `app`. В первый раз нужны Интернет и несколько минут для установки зависимостей. Модели украинского, русского и английского языков загружаются автоматически из официального репозитория с проверкой SHA-256.
5. Дождитесь открытия программы в браузере. Оставьте окно запуска открытым; для остановки нажмите `Ctrl+C`.

При следующих запусках достаточно того же **`START_WINDOWS.bat`**. На Windows библиотека, счётчик и выданные задания хранятся в `%LOCALAPPDATA%\Protokol\data`, поэтому новая распакованная версия использует прежнюю нумерацию. При первом переходе данные из старой папки `data` копируются туда, если постоянный каталог ещё не существует. Существующий постоянный каталог не перезаписывается.

Библиотеки, включая Pillow (`PIL`), устанавливаются автоматически в `.venv`. Проверка OCR и сервер запускаются через Python этого окружения; устанавливать библиотеки в системный Python вручную не требуется. Если в старой версии появляется `ModuleNotFoundError: No module named 'PIL'`, скачайте свежий ZIP, распакуйте целиком и запустите его `START_WINDOWS.bat`.

Если Windows скрывает расширения, файл будет называться **START_WINDOWS** с типом «Пакетный файл Windows». На компьютере с этой версией программы файл находится непосредственно в корне папки. Если его нет — скачайте свежий ZIP по ссылке в начале инструкции.

Ручной запуск через PowerShell также доступен:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
tesseract --list-langs
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для ручного запуска языки `ukr`, `rus` и `eng` должны быть установлены в Tesseract либо подготовлены утилитой `.\.venv\Scripts\python.exe scripts\prepare_ocr.py`. Если модели находятся в нестандартном каталоге, укажите путь к нему в `$env:TESSDATA_PREFIX` перед запуском. Скрипты `.sh` рассчитаны на Linux/macOS.

## Работа с актом

1. На вкладке **Акти відбору** загрузите акт. Поддерживаются PDF, JPG, PNG, TIFF, DOCX и текстовые TXT. Лимит одного файла — 25 МБ, PDF и многостраничного изображения — 20 страниц.
2. Дождитесь распознавания. Для скана нужен Tesseract с украинской моделью; PDF с текстовым слоем читается без OCR. Сложные таблицы, рукопись, размытый текст и необычная форма акта могут требовать исправления.
3. Проверьте заказчика, адрес и обстоятельства отбора, поставщика и договор. Эти сведения общие для всех позиций в текущем акте.
4. В каждой позиции проверьте название продукта, производителя, дату изготовления и объём партии. В первой позиции введите полный номер и дату протокола. Номер `87-015-3000-1305-2` продолжится как `87-015-3000-1306-2`, `87-015-3000-1307-2` и далее; дата скопируется в остальные позиции. Отдельные номера и даты можно изменить вручную или вернуть к общей последовательности. При необходимости добавьте или удалите позиции.
5. Выберите шаблон для каждой позиции. Программа предлагает варианты по названию и ключевым названиям из библиотеки; совпадение не заменяет проверку. Особенно внимательно проверяйте похожие виды продуктов и несколько шаблонов одного продукта.
6. Подтвердите проверку данных и шаблонов, затем скачайте ZIP. Внутри — отдельный Word-файл на каждую позицию и `ПЕРЕВІРИТИ.txt` со списком незаполненных полей.

Распознанный текст доступен для просмотра и исправления. Повторный разбор текста заменяет текущие распознанные поля: сохраните нужные ручные изменения перед повторным разбором. Обновление страницы браузера сбрасывает текущий акт и несохранённые исправления; библиотека шаблонов при этом сохраняется.

Если OCR не нашёл позиции, можно внести их вручную. При распознавании не выполняются инструкции из содержимого загруженных документов: текст акта используется как данные.

Кнопкой **Довідник постачальників** добавьте поставщика и назначьте ему код, например `015`. Выбор поставщика подставляет его название и вторую часть номера протокола. Начальные нули сохраняются; справочник доступен после перезапуска и обновления программы.

Отдельное поле **Код ЄДРПОУ** в довіднику постачальників добавляет код в строку поставщика. Это другой реквизит, чем код `015` в номере протокола. Кнопка **Довідник замовників** позволяет сохранять, выбирать, редактировать и удалять заказчиков; выбор заполняет строку **Замовник**. Оба справочника сохраняются после обновления программы.

Сведения об отборе берутся из акта и оформляются как «представниками військової частини … капітаном … та старшим лейтенантом …, в присутності представників …». Описание всегда заканчивается: «та направлені на проведення лабораторних випробувань до Лабораторії безпечності харчових продуктів військової частини А0873.» Неизвестные данные представителей нужно проверить и дописать вручную. Каталожный номер удаляется из конца названия продукта, когда он точно совпадает с отдельным полем **Номер за Каталогом**; масса упаковки и остальные числа сохраняются.

## Завдання для трьох відділень

На вкладке **Завдання** создаются отдельные Word-файлы для ветеринарно-санитарного, бактериологического и химико-токсикологического отделений. Можно загрузить акт прямо здесь или нажать **Підготувати завдання за цим актом** после проверки данных во вкладке протоколов.

1. Проверьте название каждого образца и поле **НД на відповідність**. Документ исследования читается из акта; номера и методы из таблиц шаблонов не подставляются вместо него автоматически.
2. При первом использовании укажите **Перший номер зразка**, например `1397`. Предварительный просмотр номеров ничего не резервирует.
3. Отметьте нужные отделения и подтвердите предложенный шаблон для каждого. Кнопка **Обрати однозначні шаблони** заполняет только пустые поля с единственным совместимым вариантом по продукту и НД; неоднозначные варианты остаются для ручного выбора. Подбор учитывает продукт и полное обозначение НД, включая номер, изготовителя в ТУ, редакцию и год. Неуточнённое мясо, несколько равнозначных вариантов или другой НД требуют проверки.
4. После выбора шаблона вес и количество проб для каждого отделения заполняются автоматически из соответствующего Word-шаблона. Любое значение можно отредактировать; ручные правки сохраняются при повторном подборе. Кнопка **Взяти з шаблону** возвращает значение выбранного шаблона. Если нужно одно значение для отделений, укажите общую весовую характеристику: она применяется к полям без ручных правок. Общий вес отбора не делится на три автоматически. Явно очищенное поле в документе будет обозначено `[НЕ ЗАПОВНЕНО]`.
5. Подтвердите проверку и создайте ZIP. Один образец получает один номер во всех его заданиях; следующий образец — следующий номер. Дата выдачи автоматически равна дню формирования по **Europe/Kyiv**, независимо от часового пояса сервера.

Если автоматический подбор не нашёл подходящий вариант, включите нужное
отделение и нажмите на поле выбора шаблона. В отдельном окне доступны все
его шаблоны: поиск по названию, НД, синониму или имени файла и просмотр
Word-образца рядом со списком. Нажмите **Обрати цей шаблон** и подтвердите
ручной выбор. НД и методы остаются из выбранного шаблона. Ручной выбор
сохраняется в черновике; после восстановления нужно подтвердить его снова.

Нумерация в колонтитуле задания заполняется полями Word: **Сторінка 1 з 2**,
**Сторінка 2 з 2** и далее. Текущая страница и общее число страниц
пересчитываются редактором при открытии и печати, включая случаи, когда
длинное название или ручные изменения увеличили документ до нескольких страниц.

Кнопка **Хто видає завдання** открывает справочник лиц: укажите имя и фамилию, должность или звание и нажмите **Використовувати**. Выбранная запись сохраняется для следующих запусков. Она заменяет только строку «Сформулював та видав завдання»/«Видав» в каждом задании; строка получателя остаётся из формы. Без выбора сохраняется лицо из Word-шаблона.

После формирования появляется **Друкувати по 2 примірники**. Прямой друк работает в Windows с настольным Microsoft Word и принтером по умолчанию, настроенным для печати на бумаге. Подтвердите проверку комплекта: каждый Word-файл выбранных отделений будет передан в очередь в двух экземплярах. Друк использует последний сформированный комплект, не меняет номера и дату. После правки полей сформируйте комплект снова. Изменения в отдельно скачанном Word-файле автоматически в программу не возвращаются. На других системах скачайте ZIP и распечатайте файлы в своём редакторе.

Счётчик сохраняется только после успешного формирования. Сбой Word-шаблона не расходует номер. **Повторне скачування** того же комплекта возвращает прежний ZIP и не увеличивает счётчик; исходная дата также сохраняется. Исправление веса или добавление ещё одного отделения для уже выданного образца сохраняет его номер. Новый номер получает только новая позиция с новым идентификатором; это видно в предварительном просмотре. Кнопкой **Задати початковий номер** можно установить любое положительное число, включая меньшее: новые образцы начнут с него. Старые файлы и присвоенные им номера сохраняются. Ручной выбор может повторить ранее использованный номер.

Если название совместимо, но НД шаблона отличается от акта, вариант помещается в отдельную группу. Для него необходимо отдельное подтверждение **Підтверджую застосування НД цього шаблону**. В документе остаётся НД выбранного шаблона вместе с его методами; программа не объявляет разные стандарты равнозначными.

На вкладке **Шаблони завдань** доступны 60 предоставленных форм: 22 ветеринарно-санитарные, 22 химико-токсикологические и 16 бактериологических. Можно добавить, скачать и удалить форму, изменить её название, синонимы и область применения. Отделение и НД определяются по содержимому Word. Два файла с одинаковым названием сохранены как отдельные варианты.

По подтверждению пользователя бактериологический файл «бак каші, картопля готові други страви.docx», в котором примером указана квасоля, применяется **ко всем готовым вторым блюдам**. Для ветеринарно-санитарных и химико-токсикологических форм группа круп и картофеля не смешивается с бобовыми. Мясорастительные консервы остаются отдельной формой продукта.

Для своих шаблонов поддерживаются обычные подписи из образцов и метки `{{sample_number}}`, `{{product_name}}`, `{{sample_weight}}`, `{{standard}}`, `{{issue_date}}`, а для выбранного лица — `{{issuer_name}}` и `{{issuer_position}}`. НД должен быть конкретно указан в шаблоне, чтобы его можно было подобрать. Таблицы методов, оформление и остальные подписи сохраняются из формы; при необходимости обновите их в самом Word-шаблоне перед загрузкой.

## Excel за актом і протоколами

Зведена таблица создаётся сразу по встроенной форме УБХП из предоставленного
образца `0_Додаток зведена таблиця.xlsx`. Сохраняются синяя шапка, чередование
строк, ширина столбцов, форматы дат и массы, фильтры и настройки страницы.
Выбирать и загружать файл Excel больше не требуется. Каждое формирование
создаёт новую книгу `Додаток_зведена_таблиця.xlsx` с протоколами текущего списка.

Чтобы подготовить Excel сразу из акта, проверьте поля позиций и нажмите
**Підготувати Excel за цим актом**. Текущие исправления, номера и даты протоколов
переносятся на вкладку Excel. Создавать Word и выбирать его шаблоны для этого
не требуется. Номер и дата акта не подменяют реквизиты протокола.

1. Для готовых протоколов откройте **Excel** и добавьте DOCX, PDF или ZIP либо
   нажмите **Excel із цих протоколів** после создания Word. До 100 протоколов,
   по 25 МБ, общий размер загрузки до 100 МБ. Сканы распознаются локально.
2. Проверьте поля и предупреждения. В D–N записываются данные протоколов.
   M и N содержат коды ЄДРПОУ как текст с начальными нулями. Неоднозначный или
   отсутствующий код остаётся пустым. Совпадение с довідником постачальників
   используется только при отсутствии кода в исходном документе.
3. H — обозначение партии — заполняется датой изготовления. E/I/J сохраняются
   как даты Excel, K — масса партии в кг, L — масса одной упаковки в кг:
   `9 ж/б по 525 г (4,725 кг)` даёт **0,525**. «Вжити до» не подменяет дату
   изготовления. Столбцы O/P сохраняются в форме и остаются незаполненными.
4. Подтвердите проверку и нажмите **Створити Excel**. Отдельно доступен отчёт
   проверки. Установленные Microsoft Excel и Word для создания XLSX не нужны.

Старые черновики сохраняют введённые данные и открываются без повторного
выбора книги. Если черновик раньше дополнял загруженный XLSX, редактор
показывает уведомление: новая таблица содержит только протоколы текущего
списка, прежняя книга не дополняется и остаётся без изменений. Её сохранённая
копия остаётся доступна среди файлов соответствующего пакета.

Ядро заполнения D–N перенесено из [Протокол → Excel](https://github.com/Rostislav999/-)
версии `b6f448e`. Встроенная форма содержит только структуру и оформление;
исходные служебные идентификаторы и сведения о компьютере в неё не включены.
Инструкции из документов не выполняются, значения ячеек записываются как
текст или числа, а не как формулы. Обработка выполняется на компьютере;
готовая таблица сохраняется в текущем пакете документов.

## Библиотека шаблонов

На вкладке **Бібліотека шаблонів** можно загрузить новый `.docx`, изменить название и категорию, настроить ключевые названия для поиска, скачать исходный шаблон или удалить его из рабочей библиотеки. Например, для шаблона свинины используйте ключевые названия `свинина тушкована` и `свинина`; для первого блюда — конкретное название супа и `готова перша страва`. Предпочтительны точные названия продукта.

Готовые вторые блюда разделены на группы **Бобові**, **Круп’яні**, **Картопляні** и **Інші**. Группу можно указать при загрузке и редактировании шаблона; по наименованию блюда программа также различает фасоль, горох, чечевицу, гречку, ячневую крупу, рис и картофель. Несовместимые группы не подменяют друг друга. При неопределённой группе требуется ручной выбор.

Исходные образцы в `assets/templates` не изменяются. При первом запуске они копируются в подпапку `templates` рабочего каталога данных. Дальнейшие изменения и удаления сохраняются в ней; повторный запуск не восстанавливает удалённые записи автоматически. Новые встроенные образцы из обновления добавляются один раз без сброса пользовательской библиотеки. Для полной резервной копии используйте кнопку **Резервні копії**. Исходные PDF/фото актов в архив не входят, а распознанный текст и исправления входят вместе с сохранёнными черновиками.

Новый шаблон должен содержать контрольную фразу и распознаваемые поля перед ней. Можно взять один из предоставленных образцов с украинскими подписями полей или расставить в Word текстовые метки:

| Метка | Содержание |
| --- | --- |
| `{{protocol_number}}` | Номер протокола и идентификационный номер образца |
| `{{protocol_date}}` | Дата протокола |
| `{{customer}}` | Заказчик |
| `{{catalog_number}}` | Номер по каталогу продуктов |
| `{{product_name}}` | Название образца |
| `{{sampling_description}}` | Адрес и обстоятельства отбора |
| `{{manufacturer}}` | Производитель |
| `{{supplier}}` | Поставщик |
| `{{contract}}` | Договор |
| `{{manufacture_date}}` | Дата изготовления / срок годности |
| `{{batch_size}}` | Размер партии |
| `{{act_number}}` | Номер акта отбора |
| `{{act_date}}` | Дата акта отбора |
| `{{seal_number}}` | Номер пломбы или сейф-пакета образца |
| `{{sample_weight}}` | Количество упаковок, масса упаковки и общая масса образца |

Минимально необходимы номер и дата протокола, название образца, заказчик и сведения об отборе. Программа сообщает об отсутствующих полях шаблона и не позволяет незаметно потерять введённые данные. После контрольной фразы заполняются поля акта, пломбы и веса, а также распознанные строки образца в таблице, цели и заключении, перечисленные выше. Остальной текст сохраняется и отмечается красным. В колонтитулах обновляется номер протокола: обычная подпись «Протокол випробувань №…», совпадающий номер или `{{protocol_number}}`. Обычные подписи из образцов (`Замовник:`, `Виробник:`, `Договір:` и другие) также поддерживаются. Неизвестная метка до контрольной фразы или отсутствие самой фразы вызывает ошибку загрузки шаблона.

## Данные и ограничения

Сканы обрабатываются на компьютере, где запущен сервер. Внешние сервисы распознавания не используются, ключи API не нужны. Загруженный акт и ZIP протоколов не сохраняются в рабочую библиотеку; временные изображения OCR удаляются после обработки. Распознанный текст, поля и сведения об их источниках сохраняются локально в черновиках и входят в резервные копии. Для заданий сохраняются шаблоны, настройки, счётчик и выданные ZIP в локальной базе `numbering.sqlite3`: это позволяет повторно скачать тот же комплект с теми же номерами и датой. Акты и базы с выданными заданиями не включаются в GitHub и в архив исходников.

Сервер по умолчанию слушает только `127.0.0.1`. Это программа для локального использования, без пользователей и авторизации; не публикуйте её напрямую в интернете и не меняйте адрес на общедоступный без отдельной настройки доступа. Каталог постоянных данных можно задать переменной `PROTOKOL_DATA_DIR`. Windows-файл запуска по умолчанию использует `%LOCALAPPDATA%\Protokol\data`. При прямом запуске сервера и на Linux/macOS по умолчанию используется `data` в каталоге проекта.

## Проверки для разработки

После установки зависимостей:

```bash
.venv/bin/python -m pytest
```

На Windows: `.\.venv\Scripts\python.exe -m pytest`. Проверки охватывают разбор данных, подбор шаблонов и генерацию DOCX; запуск тестов сам по себе не подтверждает точность OCR для любого нового скана. Для реальной работы всегда проверяйте распознанные значения и выбранный шаблон.

## Проверено на присланных образцах

На трёхстраничном скане акта распознаны все 11 строк: наименования, производители, даты изготовления, размеры партий и нормативные документы на соответствие. Рукописные номера не считаются надёжно распознанными и остаются для ручного ввода. Поля заказчика и даты протокола не выводятся из догадок.

Для трёх позиций печёночного паштета из акта добавлен предоставленный шаблон 814. Шаблоны мясного паштета и печени трески для этих строк не предлагаются. Для строки «М’ясо тушковане» без указания вида мяса требуется ручная проверка.

Проверены создание Word-файлов, сохранность всех 22 шаблонов после контрольной фразы, распознавание табличных строк, подбор продуктов, API и управление библиотекой. Браузерная проверка включает создание ZIP и работу интерфейса на мобильном экране.

## Супровідні листи за протоколами

У лівому меню відкрийте окремий розділ **Супровідні**.
Виберіть одночасно готові протоколи DOCX/PDF або ZIP із ними та, за потреби,
таблицю XLSX. Натисніть **Прочитати комплект**. Таблиця повинна містити номер
протоколу в D, дату в E, постачальника в M; рядки зіставляються за повним номером,
а не порядком файлів. У комплект потрапляють лише завантажені протоколи.
Значення Excel мають пріоритет; розбіжності з протоколами показуються для перевірки.

Перевірте назву кожної фірми, її код, номер, дату й кількість аркушів. Назва фірми
може визначатися зі збереженого довідника за кодом постачальника з номера протоколу
або за ЄДРПОУ. Якщо назви немає, введіть її вручну. Кількість сторінок PDF
визначається з файлу. Для DOCX увімкніть **Порахувати аркуші в локальному
редакторі**: програма відкриє тимчасові копії у встановленому Microsoft Word
(або LibreOffice) і перерахує сторінки. Оригінали не змінюються. Без редактора
або після помилки підрахунку показуються метадані з попередженням — кількість
аркушів можна вказати вручну. Програма не визначає двосторонній друк.

Підписи заповнені за наданими зразками та доступні для редагування. За потреби
вкажіть виконавця й телефон. Додаткові документи (наприклад, інформацію про
невідповідності) внесіть окремими рядками з кількістю аркушів і примірників;
вони не додаються автоматично за результатами випробувань. Позначте Excel у
переліку додатків лише якщо надсилатимете таблицю.

Натисніть **Переглянути й відредагувати листи**. Для загальної супровідної та
кожної фірми можна окремо змінити адресатів, основний текст, додатки, посаду,
підпис і контакт. Кожен рядок основного тексту стане окремим абзацом; додатки
вводяться з нового рядка без номерів — нумерація додається автоматично.
Зміна реквізитів комплекту скидає редактор: сформуйте листи заново.

Оберіть лист у компактному списку над редактором. У режимі **Поруч** текст і
сторінка розташовані поряд. **Текст** і **Сторінка** розгортають потрібну область
на всю ширину. Після правки сторінка оновлюється автоматично. Масштаб
можна змінити. Додатки, підпис і контакти відкриваються окремо за потреби.
Це орієнтовний вигляд документа: остаточну пагінацію й друк визначає Word.
Перегляд працює локально всередині вікна програми, без зовнішніх сервісів.

Панель **Перевірити**, вибору формату та створення документа закріплена внизу.
У меню **Ще** доступні ручне збереження чернетки та повторне завантаження
останнього Word/PDF. Поруч видно стан автозбереження. Угорі перемикайте
**Звичайний текст** / **Збільшений текст** — вибір зберігається після перезапуску.
Резервні копії відкриваються кнопкою внизу лівого меню.

Після перевірки тексту підтвердьте дані й натисніть **Завантажити супровідні ZIP**. Архів
містить одну загальну супровідну на ДП МОУ «Агенція оборонних закупівель» та
Управління безпечності харчових продуктів та ветеринарної медицини й окремі
супровідні для кожної фірми лише з її протоколами. Вихідні протоколи й Excel
до цього архіву не копіюються. Штамп зліва містить тризуб, назву міністерства,
військову частину А0873, email, код ЄДРПОУ 26614722 та порожні поля дати й номера.
Герб і весь текст штампа оформлені одним синім кольором, незалежно від теми Word.
Email і код частини розташовані над полями дати й номера. У правому блоці
листа фірмі друкується її назва без позначеного коду ЄДРПОУ, зокрема для
відновлених та відредагованих листів. Код у вихідних даних і довіднику зберігається.

Листи заповнюються у вихідних Word-зразках зі збереженням полів сторінки,
розташування штампа, шрифтів, абзацних відступів та інтервалів. Рядки додатків
успадковують оформлення зразка незалежно від кількості протоколів. Довгий
комплект може займати кілька сторінок; посада та підпис залишаються разом.
Порожні абзаци після останнього підпису або контакту прибираються, щоб не
створювати зайву чисту сторінку наприкінці листа.

Вихідні файли не змінюються. Реквізити комплекту, підписи та відредаговані
супровідні автоматично зберігаються локально під час роботи. Після перезапуску
натисніть **Відновити** біля чернетки **Супровідні листи**. Текст, абзаци й
додатки можна далі редагувати та завантажувати без повторного імпорту протоколів.
Підтвердження перевірки потрібно поставити знову. Чернетка входить у резервні
копії програми; вихідні файли протоколів і Excel до неї не копіюються.
Нові залежності для цієї функції не потрібні. Windows-інсталятор потрібно
перезібрати з оновленого коду стандартним workflow репозиторію.

### Журнал вихідних і профілі підписантів

У блоці **Номер і дата листа** введіть вихідні реквізити окремо для кожного
адресата. Вони потрапляють у штамп і журнал; без реквізитів залишаються поля
зразка. Номер вводиться вручну, разом із датою. Повторення одного вихідного
номера в межах року перевіряється до збереження всього комплекту.

Готові супровідні автоматично записуються в **Журнал вихідних** разом із самими
Word-файлами. Кнопка **Зберегти в журнал як чернетку** доступна до остаточного
підтвердження. Статуси: **Чернетка**, **Готово**, **Надіслано**. Позначку
відправлення та примітку змінюйте у відкритому записі. Пошук знаходить фірму,
вихідний номер, номер протоколу та текст примітки; доступні фільтри дат і статусів.
Повторне скачування готового комплекту не дублює записи. З журналу можна
завантажити збережений Word, отримати PDF або відкрити **Редагувати копію**.
Копія отримує нове формування з порожніми вихідними реквізитами.

Кнопка **Підписанти** відкриває збережені профілі: назва, посада, звання й ім’я,
виконавець і телефон. Профіль можна вибрати для окремого листа або призначити
для нових загальних листів та листів фірмам. Ручні правки тексту зберігаються.
Профілі, журнал із файлами та розмір тексту входять у резервну копію.

### PDF

У нижній панелі оберіть **PDF · ZIP** перед створенням протоколів, завдань або
супровідних. Для перетворення потрібен локально встановлений Microsoft Word
або LibreOffice; редактор не входить у Windows-установщик. Word-файли доступні
навіть без нього. Перевірка наявності редактора не запускає Word і не друкує
документи. Сам експорт працює на тимчасових копіях без збереження оригіналів.

Помилка PDF не видаляє сформований Word і не споживає нові номери зразків.
Скористайтеся **Ще → Завантажити останній Word/PDF** для повторної спроби.
Файл `ПЕРЕВІРИТИ.txt` з архіву протоколів також зберігається в PDF-комплекті.
