# Протокол

[Скачать программу ZIP](https://github.com/Rostislav999/protokol/archive/refs/heads/main.zip)

Скачайте и распакуйте архив, затем выполните установку по инструкции ниже. Для запуска нужны Python 3.12+ и Tesseract OCR 5.

Локальная программа для подготовки Word-протоколов по акту отбора образцов. Загружаете PDF или фото акта, проверяете распознанные позиции, выбираете подходящий шаблон для каждой позиции и скачиваете ZIP с отдельными файлами `.docx`.

В библиотеку включены 22 предоставленных образцов: мясные и рыбные консервы, готовые блюда, каши, паштеты, джемы, сахар, соль и сухарики. Библиотеку можно дополнять через интерфейс без изменения программы.

## Что меняется в протоколе

Программа заполняет сведения **только до фразы**:

> Вищезазначена інформація надана замовником.

Весь остальной шаблон сохраняется: таблицы, результаты испытаний, подписи, даты и оформление ниже этой фразы остаются из образца. Полученный файл — проект протокола. Перед использованием отдельно проверьте эту сохранённую часть; новые результаты испытаний программа не рассчитывает и не подтверждает.

Старые данные заказчика и образца из начала шаблона не используются как значения по умолчанию. Незаданные поля получают отметку `[НЕ ЗАПОВНЕНО]`. Номер и дату протокола нужно проверить и указать отдельно: дата акта не считается датой протокола.

## Установка и запуск

Нужны Python 3.12 или новее и Tesseract OCR 5. Node.js, Microsoft Word и платные API для работы сервера не требуются. Word или совместимый редактор понадобится для просмотра и окончательной проверки документов.

### Linux или macOS

Установите Python с модулем `venv` и Tesseract через пакетный менеджер своей системы. Например, для Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install python3-venv tesseract-ocr
```

Версия Python в системе должна быть не ниже 3.12. Для macOS с Homebrew:

```bash
brew install python@3.12 tesseract
```

В каталоге проекта выполните:

```bash
./scripts/setup.sh
./scripts/run.sh
```

Если нужный Python вызывается другим именем, используйте, например, `PROTOKOL_PYTHON=python3.12 ./scripts/setup.sh`.

Установочный скрипт создаёт `.venv`, устанавливает зависимости и загружает официальные модели `ukr`, `rus`, `eng` в `.local/tessdata`. Модели закреплены за конкретным коммитом проекта `tesseract-ocr/tessdata_fast`; перед использованием проверяется SHA-256. Зависимости закреплены с контрольными суммами в `requirements.lock`. Повторный запуск проверяет имеющиеся модели и устанавливает закреплённые зависимости, не сбрасывая библиотеку.

Для первой установки нужен HTTPS-доступ к PyPI и `raw.githubusercontent.com`. После установки распознавание и генерация выполняются локально. Проверки TLS и контрольных сумм отключать не нужно.

После запуска откройте в браузере адрес `http://127.0.0.1:8000`. Для другого порта: `PROTOKOL_PORT=8001 ./scripts/run.sh`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

### Windows

Установите Python 3.12+ и Tesseract OCR 5; добавьте `tesseract.exe` в `PATH`. Установщик Tesseract должен включать украинскую, русскую и английскую модели (`ukr`, `rus`, `eng`). В PowerShell в каталоге проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
tesseract --list-langs
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В выводе `tesseract --list-langs` должны присутствовать `ukr`, `rus` и `eng`. Если языковые модели находятся в нестандартном каталоге, укажите путь к нему в `$env:TESSDATA_PREFIX` перед запуском. Скрипты `.sh` рассчитаны на Linux/macOS; команды Windows приведены для ручной установки.

## Работа с актом

1. На вкладке **Акти відбору** загрузите акт. Поддерживаются PDF, JPG, PNG, TIFF, DOCX и текстовые TXT. Лимит одного файла — 25 МБ, PDF и многостраничного изображения — 20 страниц.
2. Дождитесь распознавания. Для скана нужен Tesseract с украинской моделью; PDF с текстовым слоем читается без OCR. Сложные таблицы, рукопись, размытый текст и необычная форма акта могут требовать исправления.
3. Проверьте заказчика, адрес и обстоятельства отбора, поставщика и договор. Эти сведения общие для всех позиций в текущем акте.
4. В каждой позиции проверьте название продукта, производителя, дату изготовления и объём партии. Введите номер и дату протокола. При необходимости добавьте или удалите позиции вручную.
5. Выберите шаблон для каждой позиции. Программа предлагает варианты по названию и ключевым названиям из библиотеки; совпадение не заменяет проверку. Особенно внимательно проверяйте похожие виды продуктов и несколько шаблонов одного продукта.
6. Подтвердите проверку данных и шаблонов, затем скачайте ZIP. Внутри — отдельный Word-файл на каждую позицию и `ПЕРЕВІРИТИ.txt` со списком незаполненных полей.

Распознанный текст доступен для просмотра и исправления. Повторный разбор текста заменяет текущие распознанные поля: сохраните нужные ручные изменения перед повторным разбором. Обновление страницы браузера сбрасывает текущий акт и несохранённые исправления; библиотека шаблонов при этом сохраняется.

Если OCR не нашёл позиции, можно внести их вручную. При распознавании не выполняются инструкции из содержимого загруженных документов: текст акта используется как данные.

## Библиотека шаблонов

На вкладке **Бібліотека шаблонів** можно загрузить новый `.docx`, изменить название и категорию, настроить ключевые названия для поиска, скачать исходный шаблон или удалить его из рабочей библиотеки. Например, для шаблона свинины используйте ключевые названия `свинина тушкована` и `свинина`; для первого блюда — конкретное название супа и `готова перша страва`. Предпочтительны точные названия продукта.

Готовые вторые блюда разделены на группы **Бобові**, **Круп’яні**, **Картопляні** и **Інші**. Группу можно указать при загрузке и редактировании шаблона; по наименованию блюда программа также различает фасоль, горох, чечевицу, гречку, ячневую крупу, рис и картофель. Несовместимые группы не подменяют друг друга. При неопределённой группе требуется ручной выбор.

Исходные образцы в `assets/templates` не изменяются. При первом запуске они копируются в рабочую библиотеку `data/templates`. Дальнейшие изменения и удаления сохраняются в ней; повторный запуск не восстанавливает удалённые записи автоматически. Новые встроенные образцы из обновления добавляются один раз без сброса пользовательской библиотеки. Для резервной копии сохраните каталог `data` целиком. Пользовательские акты в резервную копию библиотеки не входят.

Новый шаблон должен содержать контрольную фразу и распознаваемые поля перед ней. Можно взять один из предоставленных образцов с украинскими подписями полей или расставить в Word текстовые метки:

| Метка | Содержание |
| --- | --- |
| `{{protocol_number}}` | Номер протокола и идентификационный номер образца |
| `{{protocol_date}}` | Дата протокола |
| `{{customer}}` | Заказчик |
| `{{catalog_number}}` | Номер по каталогу продуктов |
| `{{product_name}}` | Название образца |
| `{{sampling_description}}` | Адрес и обстоятельства отбора |
| `{{manufacturer}}` | Производитель |
| `{{supplier}}` | Поставщик |
| `{{contract}}` | Договор |
| `{{manufacture_date}}` | Дата изготовления / срок годности |
| `{{batch_size}}` | Размер партии |

Минимально необходимы номер и дата протокола, название образца, заказчик и сведения об отборе. Для полного заполнения добавьте все 11 полей. Программа сообщает об отсутствующих полях шаблона и не позволяет незаметно потерять введённые данные. Метки после контрольной фразы не заполняются. Неизвестная метка или отсутствие контрольной фразы вызывают ошибку загрузки шаблона. Обычные подписи, как в образцах (`Замовник:`, `Виробник:`, `Договір:` и другие), также поддерживаются. Колонтитулы не заполняются: размещайте изменяемые поля в основном тексте документа.

## Данные и ограничения

Сканы обрабатываются на компьютере, где запущен сервер. Внешние сервисы распознавания не используются, ключи API не нужны. Загруженный акт и создаваемый ZIP не сохраняются в рабочую библиотеку; обработка может использовать временные файлы OCR. Документы и распознанные сведения остаются в памяти текущего запроса и страницы браузера. Постоянно сохраняются только добавленные шаблоны и их настройки.

Сервер по умолчанию слушает только `127.0.0.1`. Это программа для локального использования, без пользователей и авторизации; не публикуйте её напрямую в интернете и не меняйте адрес на общедоступный без отдельной настройки доступа. Каталог постоянных данных можно задать переменной `PROTOKOL_DATA_DIR`; по умолчанию используется `data` в каталоге проекта.

## Проверки для разработки

После установки зависимостей:

```bash
.venv/bin/python -m pytest
```

На Windows: `.\.venv\Scripts\python.exe -m pytest`. В текущей версии прошли 99 тестов. Проверки охватывают разбор данных, подбор шаблонов и генерацию DOCX; запуск тестов сам по себе не подтверждает точность OCR для любого нового скана. Для реальной работы всегда проверяйте распознанные значения и выбранный шаблон.

## Проверено на присланных образцах

На трёхстраничном скане акта распознаны все 11 строк: наименования, производители, даты изготовления и размеры партий. Рукописные номера не считаются надёжно распознанными и остаются для ручного ввода. Поля заказчика и даты протокола не выводятся из догадок.

Для трёх позиций печёночного паштета из акта добавлен предоставленный шаблон 814. Шаблоны мясного паштета и печени трески для этих строк не предлагаются. Для строки «М’ясо тушковане» без указания вида мяса требуется ручная проверка.

Проверены создание Word-файлов, сохранность всех 22 шаблонов после контрольной фразы, распознавание табличных строк, подбор продуктов, API и управление библиотекой. Браузерная проверка включает создание ZIP и работу интерфейса на мобильном экране.
